# Acesso a banco relacional em Go (database/sql, pgx, sqlc, sqlx, GORM, ent)

Cobre a camada de acesso a banco relacional em serviços Go: `database/sql` e o pool, pgx/pgxpool, sqlc (SQL primeiro com código gerado), sqlx, GORM, ent, migrations (golang-migrate, goose, Atlas), transações com `context`, fechamento de `rows`, N+1 e injeção de SQL. **Não cobre** modelagem de tabelas, chaves, índices e normalização (ver `data/relational-schema-design.md`), nem regras gerais da linguagem (ver `languages/go.md`) ou da camada HTTP (ver `frameworks/go-http.md`).

## Como identificar a versão e o estilo do repositório

- `grep -E 'jackc/pgx|lib/pq|go-sql-driver/mysql|modernc.org/sqlite|mattn/go-sqlite3|gorm.io|jinzhu/gorm|entgo.io|jmoiron/sqlx|uptrace/bun|golang-migrate|pressly/goose|ariga.io/atlas' go.mod`.
- sqlc: `sqlc.yaml`/`sqlc.json`, diretório `query/`/`queries/` com `-- name: X :one`, código com cabeçalho `// Code generated by sqlc. DO NOT EDIT.`
- pgx nativo vs `database/sql`: `grep -rn 'pgxpool.New\|pgx.Connect\|stdlib.OpenDB\|sql.Open("pgx"' --include=*.go`.
- `lib/pq` em código novo: aceitável, mas a comunidade prefere pgx para PostgreSQL [comunidade].
- GORM: `AutoMigrate(` no `main`; `gorm.Config{` (SkipDefaultTransaction, PrepareStmt).
- ent: diretório `ent/schema/`, `ent/generate.go` com `//go:generate`.
- Migrations: `migrations/`, `db/migrations/`, `atlas.hcl`, `atlas.sum`.

## Estrutura e arquitetura recomendadas

**Oficial (go.dev, tutoriais de banco):** um `*sql.DB` (ou pool) de vida longa, compartilhado e seguro para concorrência; métodos com sufixo `Context`; placeholders, nunca `fmt.Sprintf`; transações via `BeginTx` + `defer tx.Rollback()` + `Commit`.

**Comunidade — escolha de abstração:**
- **sqlc (SQL primeiro):** você escreve SQL, ele gera funções e structs tipadas; sem reflexão em runtime. Bom para times que dominam SQL e querem revisão de consulta no PR.
- **pgx nativo:** quando o alvo é só PostgreSQL e se quer `COPY`, `LISTEN/NOTIFY`, tipos nativos e melhor desempenho; `database/sql` (via `pgx/stdlib`) quando outra biblioteca exige essa interface.
- **sqlx:** extensão leve de `database/sql` (scan para struct, `In`, named params).
- **GORM:** produtividade em CRUD convencional; custo em reflexão, comportamento implícito (hooks, zero values, transação padrão) e SQL menos visível no review.
- **ent:** schema como código Go, grafo de arestas, tipagem em compile time; custo em geração de código e curva de aprendizado.
Nenhuma é "a oficial"; julgue pela regra que o repositório escolheu e pela consistência.

**Camadas:** pacote de repositório por domínio (`internal/order/store.go`) recebendo o pool/`Querier`; o serviço controla a transação passando um `DBTX` (interface que `*sql.DB`, `*sql.Tx`, `pgxpool.Pool` e `pgx.Tx` satisfazem — padrão que o sqlc gera). Migrations em diretório próprio, aplicadas por passo de deploy ou job, não no boot de várias réplicas ao mesmo tempo.

## Checklist de revisão

### A. Arquitetura e camadas

- **Um pool por banco, criado em `main`/`run` e injetado** — `sql.Open`/`pgxpool.New` por requisição esgota conexões. *Como checar:* `grep -rn 'sql.Open\|pgxpool.New\|gorm.Open' --include=*.go` fora de `cmd/`/`main`. *Régua:* oficial. *Vale a partir de:* todas. *Severidade típica:* Crítica se por requisição; Média se global de pacote.
- **Transação controlada pelo serviço, não pelo repositório isolado nem pelo handler** — operações que precisam ser atômicas usam o mesmo `Tx`. *Como checar:* serviço chamando dois repositórios que abrem cada um sua transação. *Régua:* comunidade. *Vale a partir de:* todas. *Severidade típica:* Alta (inconsistência).
- **Tipos de persistência não vazam para a API** — struct GORM/ent/sqlc serializada direto no JSON expõe colunas internas. *Como checar:* `json:` em modelos GORM; handlers devolvendo `ent.User`/`db.User`. *Régua:* comunidade. *Vale a partir de:* todas. *Severidade típica:* Média (Alta se expõe hash de senha/PII).

### B. Estrutura de arquivos e convenções

- **Código gerado não editado e em dia** — sqlc/ent: regenerar e comparar. *Como checar:* `sqlc diff` ou `sqlc generate && git diff --exit-code`; `go generate ./ent && git diff --exit-code`. *Régua:* oficial (ferramentas). *Vale a partir de:* todas. *Severidade típica:* Média.
- **Migrations versionadas, imutáveis e revisáveis** — arquivo já aplicado não é editado; nomes ordenáveis; `atlas.sum` atualizado quando usado. *Como checar:* `git log --follow` em migration antiga alterada; `atlas migrate validate`. *Régua:* oficial (golang-migrate, goose, Atlas). *Vale a partir de:* todas. *Severidade típica:* Alta.
- **`AutoMigrate`/`Schema.Create` fora do caminho de produção** — GORM avisa que não remove colunas e recomenda migrations versionadas; ent idem com Atlas. *Como checar:* `grep -rn 'AutoMigrate(\|Schema.Create(' --include=*.go | grep -v _test`. *Régua:* oficial (GORM, ent). *Vale a partir de:* GORM v2, ent 0.14. *Severidade típica:* Alta.

### C. Qualidade do código

- **`defer rows.Close()` logo após checar o erro e `rows.Err()` depois do laço** — sem `Close` a conexão não volta ao pool; sem `rows.Err()` um erro no meio da iteração vira resultado parcial silencioso. *Como checar:* linters `sqlclosecheck` e `rowserrcheck`; `grep -rn 'QueryContext\|\.Query(' -A3 --include=*.go | grep -c 'defer rows.Close'`. pgx: `pgx.CollectRows` fecha sozinho. *Régua:* oficial. *Vale a partir de:* todas. *Severidade típica:* Alta.
- **`sql.ErrNoRows`/`pgx.ErrNoRows`/`gorm.ErrRecordNotFound` com `errors.Is` e traduzidos para erro de domínio** — comparar com `==` falha com wrapping; vazar o erro do driver acopla o serviço ao banco. GORM só devolve `ErrRecordNotFound` em `First`/`Take`/`Last`, não em `Find`. *Como checar:* `grep -rn 'ErrNoRows\|ErrRecordNotFound' --include=*.go`. *Régua:* oficial. *Vale a partir de:* todas. *Severidade típica:* Média.
- **Métodos com `Context` em todo acesso** — `db.Query` sem contexto ignora timeout/cancelamento. GORM: `db.WithContext(ctx)`. *Como checar:* `grep -rnE '\.(Query|Exec|QueryRow|Begin)\(' --include=*.go`; linter `noctx`. *Régua:* oficial. *Vale a partir de:* todas. *Severidade típica:* Alta.
- **Colunas anuláveis tratadas** — scan de `NULL` em `string` falha em runtime. *Como checar:* colunas `NULL` no schema vs tipos no scan; `sql.Null[T]` (1.22+), ponteiros ou `pgtype`. *Régua:* oficial. *Vale a partir de:* `Null[T]` em Go 1.22. *Severidade típica:* Média.
- **GORM: zero values em `Updates` com struct** — campos `0`, `""`, `false` são ignorados silenciosamente; use `map[string]any` ou `Select(...)`. *Como checar:* `grep -rn '\.Updates(&\|\.Updates([A-Z]' --include=*.go` em campos booleanos/numéricos. *Régua:* oficial (GORM). *Vale a partir de:* GORM v2. *Severidade típica:* Alta (dado não atualizado sem erro).
- **GORM: `Save` faz upsert de todos os campos** — sobrescreve colunas não carregadas. *Como checar:* `Save(` com struct parcial. *Régua:* oficial (GORM). *Vale a partir de:* GORM v2. *Severidade típica:* Alta.
- **GORM: hooks sem efeitos externos** — hooks (`BeforeCreate`, `AfterSave`...) rodam dentro da transação; erro faz rollback; `UpdateColumn(s)` e `Session{SkipHooks: true}` os pulam. Chamada HTTP/fila dentro de hook é efeito colateral não transacional e invisível no review. *Como checar:* `grep -rn 'func (.*) \(Before\|After\)\(Create\|Update\|Save\|Delete\|Find\)(tx \*gorm.DB)' --include=*.go`. *Régua:* oficial (comportamento) + comunidade (efeitos). *Vale a partir de:* GORM v2. *Severidade típica:* Média.

### D. Dados e persistência

- **Pool configurado conscientemente** — `database/sql`: `SetMaxOpenConns` (padrão ilimitado), `SetMaxIdleConns` (padrão 2), `SetConnMaxLifetime`/`SetConnMaxIdleTime` (padrão sem limite); pgxpool: `MaxConns` padrão = maior entre 4 e `NumCPU`, `MaxConnLifetime` padrão 1h. Soma de conexões de todas as réplicas ≤ limite do banco/proxy. *Como checar:* `grep -rn 'SetMaxOpenConns\|SetMaxIdleConns\|SetConnMax\|MaxConns\|pool_max_conns' --include=*.go`; `DB.Stats()` exposto em métrica. *Régua:* oficial. *Vale a partir de:* todas. *Severidade típica:* Média (Alta se ilimitado contra banco pequeno).
- **Transação com `BeginTx(ctx)` + `defer tx.Rollback()` + `Commit` checado** — `Rollback` após `Commit` é inofensivo; cancelamento do `ctx` faz rollback. Dentro da transação, usar só o `tx` — chamar `db` executa fora dela e pode causar deadlock com pool pequeno. *Como checar:* `grep -rn 'BeginTx\|Begin(' -A4 --include=*.go`; funções que recebem `tx` e usam `r.db`. GORM: `db.Transaction(func(tx *gorm.DB) error {...})`; pgx: `pgx.BeginFunc`. *Régua:* oficial. *Vale a partir de:* todas. *Severidade típica:* Alta.
- **Sem IO externo dentro da transação** — chamada HTTP segurando transação aberta prende conexão e locks. *Como checar:* `http.`/cliente gRPC entre `BeginTx` e `Commit`. *Régua:* comunidade. *Vale a partir de:* todas. *Severidade típica:* Alta.
- **Sem N+1** — consulta dentro de laço sobre resultado de outra consulta. GORM: `Preload` (uma consulta por associação) ou `Joins`; ent: `With<Edge>()` faz uma consulta extra **por aresta**, não por linha; sqlc/sqlx: `JOIN` ou `WHERE id = ANY($1)`. *Como checar:* `grep -rn 'for .*range' -A6 --include=*.go | grep -E 'Query|Get|First|Find|Only'`; log de SQL em teste de integração. *Régua:* oficial (GORM/ent docs) + comunidade. *Vale a partir de:* todas. *Severidade típica:* Média (Alta em rota quente).
- **Leitura de lote grande em streaming** — GORM `FindInBatches`/`Rows`; `rows.Next()` em vez de carregar tudo; `SELECT` com colunas explícitas. *Como checar:* `Find(&slice)` sem `Limit` em tabela grande; `SELECT *`. *Régua:* oficial (GORM performance). *Vale a partir de:* todas. *Severidade típica:* Média.
- **Migration perigosa sinalizada** — `DROP`, renomear coluna usada pela versão anterior, `ALTER` com rewrite/lock em tabela grande, índice sem `CONCURRENTLY` no PostgreSQL (com goose: `-- +goose no transaction`). Mudança incompatível deve ser feita em etapas (expandir → migrar → contrair). *Como checar:* ler cada migration do PR; `atlas migrate lint` se houver Pro ou binário community. *Régua:* oficial (Atlas, goose) + comunidade (expand/contract). *Vale a partir de:* todas. *Severidade típica:* Alta (Crítica se perde dado).
- **Estado dirty do golang-migrate tem runbook** — falha deixa a versão marcada como dirty e bloqueia próximas. *Como checar:* README/runbook menciona `migrate force`. *Régua:* oficial (FAQ). *Vale a partir de:* golang-migrate v4. *Severidade típica:* Baixa.
- **Modelagem, chaves, índices e constraints** — ver `data/relational-schema-design.md`.

### E. Segurança e privacidade

- **Nada de SQL concatenado com entrada do usuário** — `fmt.Sprintf`/`+` em consulta é injeção. Em GORM, aceitam SQL cru e são perigosos com entrada do usuário: `Where`/`Not`/`Or` com string, `Select`, `Distinct`, `Pluck`, `Order`, `Group`, `Having`, `Joins`, `Table`, `Raw`, `Exec` e condições inline em `First`/`Find`/`Delete`. Ordenação dinâmica deve usar allowlist de colunas. *Como checar:* `grep -rnE 'Sprintf\(.*(SELECT|INSERT|UPDATE|DELETE|WHERE|ORDER BY)' -i --include=*.go`; `grep -rn '\.Order(\|\.Raw(\|\.Where(fmt' --include=*.go`; `gosec` G201/G202. *Régua:* oficial (go.dev, GORM security). *Vale a partir de:* todas. *Severidade típica:* Crítica.
- **GORM: update/delete global bloqueado** — o padrão devolve `ErrMissingWhereClause`; `AllowGlobalUpdate: true` remove a proteção. *Como checar:* `grep -rn 'AllowGlobalUpdate' --include=*.go`. *Régua:* oficial. *Vale a partir de:* GORM v2. *Severidade típica:* Alta.
- **Credencial de banco fora do código e do log** — DSN com senha em constante ou logado no boot. *Como checar:* `grep -rnE 'postgres(ql)?://[^ ]+:[^ ]+@' --include=*.go`; logs que imprimem `cfg.DatabaseURL`. *Régua:* comunidade. *Vale a partir de:* todas. *Severidade típica:* Crítica.
- **TLS na conexão com banco remoto** — `sslmode=disable` em DSN de produção. *Como checar:* `grep -rn 'sslmode=disable' .`. *Régua:* comunidade. *Vale a partir de:* todas. *Severidade típica:* Alta.
- **Log de SQL sem parâmetros sensíveis** — logger do GORM em modo `Info` ou tracer do pgx gravando argumentos expõe PII. *Como checar:* `logger.Info` no `gorm.Config`; `QueryTracer` do pgx. *Régua:* comunidade. *Vale a partir de:* todas. *Severidade típica:* Alta.

### F. Integrações e mensageria

- **Evento publicado junto com a escrita usa outbox** — `Commit` seguido de `Publish` perde evento se o processo cair entre os dois; publicar antes do commit publica dado que pode sofrer rollback. *Como checar:* `Publish`/`Send` imediatamente após `Commit` ou dentro da transação. *Régua:* comunidade. *Vale a partir de:* todas. *Severidade típica:* Alta quando o evento é contrato.
- **Pool fechado no shutdown, depois do servidor HTTP** — `db.Close()`/`pool.Close()` após `srv.Shutdown`. *Como checar:* ordem dos `defer` em `main`/`run`. *Régua:* comunidade. *Vale a partir de:* todas. *Severidade típica:* Baixa.

### G. Testes

- **Repositório testado contra banco real** — testcontainers (módulo postgres/mysql) ou serviço do CI, com migrations aplicadas; mock de `*sql.DB` (sqlmock) só para caminho de erro difícil de reproduzir. *Como checar:* `grep -n 'testcontainers\|DATA-DOG/go-sqlmock' go.mod`. *Régua:* comunidade. *Vale a partir de:* todas. *Severidade típica:* Média.
- **Migrations testadas para cima (e para baixo, se o time promete down)** no CI. *Como checar:* job que roda `migrate up`/`goose up` em banco efêmero. *Régua:* comunidade. *Vale a partir de:* todas. *Severidade típica:* Média.
- **Isolamento entre testes** — transação por teste com rollback ou banco/schema por pacote. *Como checar:* testes paralelos escrevendo nas mesmas tabelas. *Régua:* comunidade. *Vale a partir de:* todas. *Severidade típica:* Baixa.

### H. Qualidade automatizada e processo

- **Linters de banco ligados** — `sqlclosecheck`, `rowserrcheck`, `gosec` (G201/G202) no golangci-lint. *Como checar:* `.golangci.yml`. *Régua:* comunidade. *Vale a partir de:* todas. *Severidade típica:* Média.
- **`sqlc vet`/`sqlc compile` no CI** quando há sqlc. *Como checar:* workflow. *Régua:* oficial (sqlc). *Vale a partir de:* sqlc com `rules`. *Severidade típica:* Baixa.

## Padrões de projeto recomendados hoje

- **Interface `DBTX` + `Queries` por transação** (padrão do sqlc: `q := db.New(tx)`). *Quando usar:* serviço que compõe várias consultas atomicamente. *Exagero:* abstrair o banco atrás de interface genérica para "trocar de banco depois". *Sinal bom:* serviço abre `tx`, cria `Queries` com ele, faz `Commit`.
- **Unit of work por função** (`store.WithTx(ctx, func(q *Queries) error {...})`). *Quando usar:* várias operações atômicas. *Exagero:* UoW global com rastreamento de entidades à la ORM pesado.
- **Repository fino por agregado**. *Exagero:* `Repository[T]` genérico que reimplementa ORM.
- **Outbox transacional** + publicador separado. *Quando usar:* evento é contrato com outro serviço. *Exagero:* evento interno de log/telemetria.
- **Expand/contract em migrations** para mudança incompatível com deploy sem downtime.
- **Bloqueio otimista por coluna de versão** (`UPDATE ... WHERE id = $1 AND version = $2`) em edição concorrente; checar `RowsAffected`.

## Anti-padrões comuns

- **`AutoMigrate` no boot de produção** com várias réplicas — corrida e mudanças não revisadas. Correção: migrations versionadas aplicadas por job.
- **`defer rows.Close()` esquecido em caminho de erro / dentro de laço** — vazamento de conexões até o pool travar. Correção: `defer` logo após o erro; função auxiliar por iteração.
- **Ignorar `RowsAffected`** em update/delete que deveria afetar uma linha — falha silenciosa. Correção: checar e mapear para `ErrNotFound`/conflito.
- **`db.Find(&user)` para buscar um registro** — varre a tabela (doc do GORM). Correção: `First`/`Take` ou `Limit(1).Find`.
- **`SkipDefaultTransaction` ligado sem saber o que perde** — o GORM envolve cada escrita numa transação por padrão (consistência com hooks/associações); desligar ganha desempenho mas tira essa garantia. Correção: ligar só com transação explícita onde há hooks/associações.
- **Consulta em `for` (N+1)**; **`SELECT *` com struct que muda**; **`LIMIT/OFFSET` profundo** em tabela grande (preferir keyset) [comunidade].
- **Driver `lib/pq` em código novo** quando pgx está disponível [comunidade].

## Segurança específica da stack

- **Protegido por padrão:** placeholders (`$1`, `?`) em `database/sql`, pgx, sqlx, sqlc e nas formas parametrizadas do GORM/ent; GORM bloqueia update/delete global; pgx usa protocolo estendido com parâmetros separados.
- **Não protegido:** qualquer string SQL montada pelo código (inclusive `ORDER BY`, nome de tabela/coluna — placeholder não serve para identificador); métodos GORM que aceitam SQL cru; `sqlx.In`/`Rebind` não validam identificadores.
- **Configurações perigosas:** `AllowGlobalUpdate`; `sslmode=disable`; logger de SQL com parâmetros em produção; usuário de banco da aplicação com permissão de DDL (só o job de migration deveria ter) [comunidade].
